= Making the Elements of Appeal Operational
:toc:
:toclevels: 2

This addendum is meant to be used alongside the main essay (`wide-appeal.md`) during design reviews and prototyping. The original essay explains *what* tends to make games travel culturally; this document is a *field guide* for *what to do next*.

If you only read one part, read the Quick start and the first table. Everything else is a set of moves you can reach for when you see a given symptom.

== Quick start (timeboxed)

*15 minutes (triage)*

* Write the game's *first-hour contract* in one sentence.
* List the top 5 repeated actions per session.
* Circle any part that feels like tax (low information, low expression).

*60 minutes (review)*

* Run the symptom table below and mark the top 3 likely failures.
* For each, pick one inoculation and one opportunity generator.
* Decide one cut, one deepening move, and one clarity move.

*3 hours (prototype sprint)*

* Build a "mature loop demo" slice (10–15 minutes of play).
* Add one hinge seed + one landmark ritual.
* Test with a fresh player for: expectation match, choice density, and returnability.

== Common symptoms → likely axis → what to do (fast table)

[cols="1,1,2", options="header"]
|===
| When players / discourse say… | Likely axis collapsing | Do this next

| “It gets good after…”
| Legible promise (and early cadence)
| Show the mature loop in the first hour; cut pre-loop chores.

| “Great, but I stopped halfway.”
| Cadence / midgame rot
| Define what changes at hours 3/6/12; recombine mechanics instead of adding new ones.

| “I can’t explain why I like it.”
| Signature primitive / symbols
| Compress the primitive into a mimable verb; add 1–2 named handles tied to consequence.

| “Grindy / podcast game.”
| Unintended friction / mushy stakes
| Increase choice density in the smallest meaningful decision; remove low-information repetition.

| “Too many systems/currencies.”
| Stakes clarity
| Collapse currencies; make a single hierarchy of value explicit; remove contradictory incentives.

| “Pretty world but it feels like a menu.”
| Mood / habitat
| Add rituals and landmarks; reduce checklist UI noise; reward presence.

| “The twist was cool but it changed nothing.”
| Recontextualization
| Build hinges that change behavior (routes, priorities, tools), not just knowledge.

| “I only log in because of dailies/season.”
| Extraction disguised as conversion
| Replace penalties with hospitality: quick re-entry, meaningful short sessions, no behindness traps.
|===

== Toolkit 1: Inoculations (guardrails)

Use these to prevent self-deception and drift. Think of them as *anti-failure tests* you can run repeatedly.

[cols="1,2,2", options="header"]
|===
| Inoculation | Tell (what you’ll observe) | Move (what to do)

| Contract audit
| “It gets good after…”; early bounces
| Write the first-hour promise; demonstrate mature loop early; delete pre-loop chores.

| Subtraction
| Discourse becomes a feature inventory
| Removal test new systems; cut parallel progression and competing micro-loops.

| Autopilot
| “Podcast game”; grind talk
| Deepen the smallest meaningful choice; add informational stakes.

| Friction cost accounting
| QoL dominates; players route around play
| List repeated actions; compress/automate/cut low-information repetition.

| Midgame rot
| Consistent quit window
| Plan novelty via recombination at hours 3/6/12/20; shorten plateaus.

| Handle economy
| Vague recall; no quotable handles
| Fewer entities; repeat with consequence; tie symbols to rituals and decisions.

| Extraction check
| Obligation language (dailies, streak anxiety)
| Separate returnability from coercion; remove punishment-for-absence.
|===

== Toolkit 2: Opportunity generators (patterns you can prototype)

Each generator is a “recipe”. Use them when you want *constructive moves*, not just audits.

=== Mature-loop demo

When to run it:: When players bounce early, or the promise feels abstract.

Recipe::
* Identify the core verb + feedback + stakes.
* Build a 10–15 minute slice that contains the loop in miniature.
* Remove any preconditions that prevent reaching the loop.

Watch for:: Can a new player describe the game truthfully after 10 minutes?

=== Competence ladder

When to run it:: When mastery is present but feels like grind or luck.

Recipe::
* Isolate one skill.
* Provide sharp feedback and stable rules.
* Recombine skills into layered challenges.

Watch for:: Players say “I can feel myself getting better.”

=== Signature compression

When to run it:: When the game is competent but culturally indistinct.

Recipe::
* Express the primitive as a single action + constraint.
* Test “mimability”: can someone mime it and be understood?
* Cut systems that compete with the primitive.

Watch for:: One-sentence description survives purchase and play.

=== Meaningful constraints

When to run it:: When coherence is weak or the game feels like a pile of options.

Recipe::
* Remove redundant tools.
* Force tradeoffs that express the intended mood.
* Make “no” visible (limits that shape play).

Watch for:: Players can infer intent from what the game disallows.

=== Hinge planting

When to run it:: When the story or structure wants a pivot but twists feel inert.

Recipe::
* Plant a repeating pattern early.
* Let players build a stable model.
* Introduce a hinge that changes priorities/routes/tools.

Watch for:: Behavior changes after the hinge (not just lore understanding).

=== Rituals + landmarks

When to run it:: When habitat strength is weak; when the world is forgettable.

Recipe::
* Define a loop ritual (prepare → depart → recover → return).
* Place a landmark inside each ritual.
* Repeat with variation and consequence.

Watch for:: Players reference places/things as handles (“meet me at ___”).

=== Anecdote engine

When to run it:: When wandering feels like transit, not story.

Recipe::
* Add roaming threats/opportunities.
* Create system collisions with aftermath.
* Allow plans to be interrupted and rerouted.

Watch for:: “I went to do X and then…” stories appear unprompted.

=== Returnability (hospitality)

When to run it:: When the game is deep but hard to re-enter.

Recipe::
* One meaningful action in < 90 seconds.
* Clear reorientation (“what matters right now”).
* Low re-learning cost.

Watch for:: Returning after a week feels welcoming, not punishing.

== Toolkit 3: Capture mechanisms (tradeoffs)

Capture is not automatically evil; it’s a set of levers with costs. Name what you’re buying.

=== Cultural capture (transmission)

[cols="1,1,2,2", options="header"]
|===
| Mechanism | Buys | Costs | Safer implementation hint

| Handle capture
| Retellability
| None (unless overstuffed)
| Tie handles to consequence and ritual; keep the cast small.

| Clip capture
| Visibility
| Design pressure toward legibility
| Design readable stakes; don’t confuse clip-worthiness with depth.

| Sentence capture
| Adoption
| Simplification pressure
| Ensure the sentence remains true at hour 10.

| Hinge capture
| Canon fuel
| Requires structural commitment
| Make hinges change behavior, not trivia.

| Scaffold capture
| Literacy expansion
| Community dependency
| Support challenge runs/mods without letting optimization erase mood.
|===

=== Behavioral capture (retention)

[cols="1,1,2,2", options="header"]
|===
| Mechanism | Buys | Costs | Safer alternative

| Loss / behindness
| Compliance
| Trust; resentment
| Hospitality returnability; meaningful short sessions.

| Variable rewards
| Excitement spikes
| Stakes fog; gambling feel
| Transparent progression + skill-linked rewards.

| Progress treadmill
| Perceived motion
| Meaning collapse
| Competence ladder (skill growth) + fewer currencies.

| Social obligation
| Deep community
| Coercion risk
| Community without punishment for absence.

| Friction hostage
| Monetization
| Reputation; respect-time breach
| Remove the friction; monetize aesthetics/expansions instead.
|===
